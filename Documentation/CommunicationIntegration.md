# Communication integration

The scene TownshipPark_Map includes Assets/Prefabs/UI/TownshipCommunications.prefab. Its UI is generated by TownshipTextChatUI using LegacyRuntime.ttf. TextChatManager is the presentation/history service; GameManager.SendChatRpc validates the actual NGO sender, filters and rate-limits before targeted delivery. Ghost/incapacitated text is delivered only to non-alive recipients. All phases allow text. History is capped at 100 messages.

## Local controls

- T / Enter opens chat; Enter sends; Escape closes. Tab cycles controls; Page Up/Down scrolls.
- Quick phrases cover location, evidence, tasks and voting. Select/right-click a message or use Players / safety for mute, block and reporting.
- Settings > Audio: read the voice notice, opt into consent, then enable voice. Hold V to transmit. Focus loss mutes the microphone.
- Voice uses Unity Services environment `productions`, project `538ef999-ef29-4b24-a1ec-f68f151200f9`, Vivox 16.12.1 and Authentication 3.8.1. Editor test mode permits local opt-in without an account permission adapter. Non-editor builds require SetVerifiedPermission from the trusted account flow.
- Proximity voice maps game XY to audio XZ and uses Vivox distance attenuation. Solid 2D colliders locally mute obstructed speakers; meetings use a group channel. Incapacitated players cannot transmit to alive participants. Audio is not recorded by this client.

## Production boundaries

This is a local integration, not a completed production moderation service. Vivox test-mode client identity registration is a routing hint, not proof of account ownership. Supply authenticated server identity mapping through SetVerifiedCommunicationAccount and implement trusted voice entitlement/channel token issuance before public release. In LAN test mode, fallback block IDs are stable for the current server session; reliable cross-session blocking needs verified persistent account IDs.

ICommunicationBackend is the report submission contract. With no backend, report metadata is saved to pending-reports.json under Application.persistentDataPath, capped at 50 records. The UI explicitly says it was saved locally and not sent. No report volume automatically bans a player. Configure authenticated submission, retention/deletion, staff review, appeals and severe-incident escalation before release. Do not store signing keys in the Unity client.

Regex filtering is a bounded first-line rule set, not contextual multilingual abuse detection or live voice moderation; see Safety system below. Distress messages remain private and do not generate punishment. The support panel labels its Malaysia-only resource; regional resource coverage remains release work.

Two-device audio/latency, microphone permissions on each target platform, screen-reader assistive technology and performance on target hardware require separate acceptance tests. Do not advertise production readiness, universal accessibility, guaranteed zero allocation or 60 FPS solely from compilation/local tests.

## Safety system

Players can read the rules in Settings > Safety > Read rules. The same panel shows their own moderation record, lets them appeal the latest decision, and lists blocked players and saved reports.

### Policy categories

`ChatSafetyFilter` sorts every message into one of these categories before anyone sees it:

| Category | Response |
| --- | --- |
| Ordinary profanity | Masked with ***. No strike. |
| Player's own contact details | Masked to protect them. No strike. |
| Targeted insult / bullying, impersonation | Blocked. Weight 1. |
| Identity-based abuse, sexual harassment, disguised lesser abuse | Blocked. Weight 2. |
| Real-world threats / doxxing, extremism, encouraging self-harm | Blocked. Severe: skips the warnings. |
| First-person distress | Never punished. The message stays private and the support panel opens. |
| Spam (bursts or the same message 3 times) | 3-second cooldown. |

"Kill" is a game verb in Crony, so "I'll kill you next round" is allowed. It only counts as a threat when it points outside the match ("irl", "where you live", etc.) or exposes someone's personal details. Letters split with spaces or symbols ("k y s", "n1gger") are judged the same as the plain text.

### Graduated enforcement (`SafetySystem`, host-authoritative)

1. **Educate**: the message is blocked, the rule is explained with a safer wording, and a warning is recorded.
2. **Restrict** (2–3 points in a match): chat pauses for 60 s and voice is restricted for the rest of the match. Every client mutes that player, and their own push-to-talk is disabled. Gameplay continues.
3. **Remove** (4+ points, or a first severe incident): the player is disconnected from the match and told why. The host can't remove itself, so its chat is locked instead.
4. **Suspend**: a 24-hour suspension after a second removal within 30 days, or 7 days for a repeated severe incident. These are flagged for human review. The automated system never issues a permanent ban.

Earlier offences count proportionately: two or more incidents in the last 30 days skip the first warning. The ledger (`safety-ledger.json`) stores only the reference, account, category, level and time, never message text. Records are deleted after 30 days. Suspensions are enforced in `SetVerifiedCommunicationAccount`. They only bind to verified accounts, because LAN session IDs can't re-identify a person.

### Reports and appeals

Reports can target a player, a message, a voice incident or a whole match, using any policy category plus "may be in distress". A distress report is treated as care: it never blocks or flags the person. Message reports include only the reported message and its time as evidence. Reports carry no reporter identity. Each subject and reason can be reported once per match, and report volume never punishes anyone by itself. A player's own decisions are kept in `my-safety-record.json`, including removals recovered from the disconnect reason. Appeals go to `ICommunicationBackend.SubmitAppealAsync`, or are queued in `pending-appeals.json` until a service exists.

### Safety architecture: what this build covers

| Component in the brief | In this project |
| --- | --- |
| Game client | Done: avatars, map, tasks, meetings, text chat, opt-in voice, local mute/block/report, accessibility settings. |
| Authoritative match server | NGO host: roles, tasks, cooldowns, sabotage, voting, victory, chat filtering and enforcement are decided by the host, and invalid RPCs are rejected. The host is a player's machine, not a trusted dedicated server. |
| Account & matchmaking service | Not built. LAN only, with session-scoped IDs. Needs authenticated pseudonymous accounts, age-appropriate communication permissions and server-side suspension status. |
| Text moderation service | First-line rules only. Context-aware multilingual classification still needs a hosted service behind the same `ChatSafetyFilter` and `SafetySystem` decision points. |
| Voice service | Vivox proximity/meeting channels with mute, block and Level 2 restriction. There is no speech recognition or live voice moderation: that needs a real-time audio service, latency and privacy review, and speech-recognition error testing. A permanent ban must never rest on an automated transcript. |
| Safety case-management | Not built. Reports, appeals and incidents are queued locally. Staff access control, audit logs, the review workflow, severe-incident escalation and law-enforcement referral procedures need a backend. |

Security requirements still open before public release: authenticated account actions, server-side rate limiting of reports and account actions, encryption in transit and at rest for the stored records (local JSON files are currently plain text), restricted evidence access, and a defined retention and deletion schedule beyond the 30-day local ledger.

## Opening a downloaded project

Install Unity 6000.6.6f1 through Unity Hub. Download the complete Unity Version Control branch, add its root folder in Hub, and allow Package Manager and asset imports to finish. Open Assets/Scenes/TownshipPark_Map.unity and press Play for local gameplay. Package versions are pinned in Packages/manifest.json and packages-lock.json. Generated Library, Temp and machine-specific Git metadata are intentionally excluded.

Local gameplay and text practice do not require Vivox credentials. Voice is off by default. For Editor voice testing, an authorized project member must configure Vivox through Unity Project Settings for their own machine; signing credentials are deliberately not distributed through version control. Public online voice and reports still require the production integrations described above.
